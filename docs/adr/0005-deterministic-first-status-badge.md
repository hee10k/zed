# Deterministic-first terminal status badge with model-only idle-vs-wait disambiguation

Terminal rows in the sidebar show a monotone status badge (Running / Idle / WaitingForUserInput / Completed). State is derived deterministically wherever possible — process alive + currently generating → Running; `ProcessExited`/no process → Completed — and the ambiguous Idle-vs-WaitingForUserInput split alone is resolved by debounced, cached model inference. The inferred result is cleared on any deterministic transition. The badge is monotone by requirement: shape, filled↔hollow state, and position carry the meaning, never hue alone, so it stays legible under colour-blindness and custom themes.

**Considered:** model inference for all four states — rejected as wasteful and laggy (a model call per keystroke is unusable); a fully deterministic scheme — rejected because idle-holding-for-input is genuinely indistinguishable from idle-alone via process signals alone. A colour-only badge was rejected because the spec explicitly requires monotone legibility. **Consequences:** the badge needs a four-state enum with a deterministic baseline plus one debounced model path; downstream tests must assert external state transitions, and the deterministic-vs-inferred split means the model path is the only non-deterministic seam and is worth isolating behind a pure predicate.
